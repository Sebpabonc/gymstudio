## 1. Problem (evidence)

change. The current screen answers the right questions only after 2–4 weeks, and until then shows
abstract stats (e1RM, tonnage, push:pull ratios) and "not enough data" lines. It never shows the
one thing a week of data *can* show: **this session vs the last time you did this, set by set.**

## 3. Chart / card audit

| Card | Verdict | Why |
|---|---|---|
| Hero "Stronger on X of Y" + avg % | **Misleading → remove** | Averages e1RM across unrelated lifts; a single % hides which lift and why. Already gated, so with 1 week it shows "not enough" — dead space at the top. |
| Stat: PRs | **Misleading → replace** | Count without context; "3 PRs" doesn't say what. Gating (3 prior) is good, keep the rule, change the presentation (Best marks). |
| Stat: Sessions | Useful → move to Consistency | Needs "of planned". |
| Stat: Streak weeks | Redundant | Same info as sessions/week strip. |
| Insights cards (mover / worst / noBest / muscle) | Partly useful | "No new best in N sessions" is useful later; "worst mover" is negative framing on % e1RM. Fold into Summary. |
| Main lifts + sparkline + % | Misleading early | % of e1RM is an estimate of an estimate; users read it as "lift X got Y% stronger". Replace with kg × reps comparison. |
| Strength chart takeaway | **Misleading** | `strengthTrend.ts:47` gives "+N %" from **2 points** and mixes A/B days via `dayType` default `'A'` inference. |
| Top-set load change | Redundant | Covered by per-exercise comparison. |
| Weekly sets per muscle | **Useful, keep** | Best muscle-group answer; must show *planned* alongside and explain the 0.5 credit. |
| Volume per session % | Misleading | kg×reps rises with easier/heavier choices; "more = better" implied by up-arrow colour. Keep as neutral context only. |
| Block tonnage | Remove for now | Needs a previous block; meaningless in week 1. |
| Push:pull / upper:lower | Remove from main view | Program-design judgement (PT), not user action; the plan already fixes it. |
| Per-exercise VolumeTrend (Plan tab) | **Misleading** | Mixes A and B days (different rep schemes), so the line zig-zags by design; up = green implies better. |
| Range toggle (Block / 4 wk / 12 wk) | Redundant now | All three identical with 1 week. Hide until ≥ 2 blocks. |

## 4. Questions Progress must answer (in priority order)

1. **Am I consistent?** Sessions this week vs plan; which day is missing.
2. **Am I improving on each exercise?** vs the *equivalent* session (same exercise + same plan day).
3. **How — load or reps?** Show both, set by set; never only an estimate.
4. **What did I beat?** Real records with date and context; first session = baseline.
5. **Which muscle groups got more/less work than planned?** Sets, not tonnage.
6. **What do I watch next session?** Short, log-backed list (PT-owned wording rules).

## 5. New screen spec

Order top → bottom. Same cards, tokens and font sizes as today (`--font-section 0.65rem`,
`--font-body 0.76rem`, `.card`, `.progress-stat`). At most **two** charts on the screen.

### 5.1 Summary (top card) — answers Q6
- **Data:** results of 5.3 for sessions in the last 7 days.
- **Computation:** per exercise logged this week, classify vs its comparison session (5.3):
  `improved` (more reps at same kg on ≥1 set without fewer elsewhere, or more kg with reps ≥ target
  — PT-RULE-1), `held` (same), `watch` (fewer total reps at same kg, or reps below target on
  ≥ PT-RULE-2 sets). Exercises with no comparison → `baseline`.
- Shows three counts + up to 3 named rows ("Incline DB press: 26→28 kg, reps held").
- **Insufficient data** — EN: "First week: these are your baselines. Next time you repeat a day
  we'll compare set by set." · ES: "Primera semana: estas son tus marcas base. Cuando repitas un
  día compararemos serie por serie."

### 5.2 Consistency — answers Q1
- **Visual:** 7-dot week strip (Mon–Sun), filled = trained, label = plan day short name; text
  "5 of 6 planned days · 119 of 135 sets".
- **Computation:** distinct `date`s with ≥1 entry in the week; planned = `block.days.length`;
  sets = working sets vs Σ planned `sets`. Missing planned day keys listed.
- **Adherence line:** reuse `adherence.ts` hit rate ("Hit target reps on 88% of sets") only when
  plannedSets ≥ 1; hide RIR-based anything (0 RIR logged).
- **Empty** — EN: "No workouts logged this week yet. Log today's first set to start." ·
  ES: "Aún no hay entrenos esta semana. Registra tu primera serie de hoy para empezar."
- Missing day — EN: "Lower body B not logged yet." · ES: "Falta registrar Pierna B."

### 5.3 Per-exercise progress — answers Q2, Q3
- **List** of this week's exercises grouped by plan day. Each row: name, latest sets as
  `kg × reps` chips, and a comparison line.
- **Comparison session (exact):** most recent earlier session with same `exerciseId` **and same
  `dayKey`**, excluding deload weeks. If none, fall back to same exercise on the *paired* day
  (A↔B) and label it "vs Chest & Back A (different rep scheme)". If none → baseline.
- **Comparison line:** `Δ top kg`, `Δ total reps at that kg`, `Δ sets`. E.g.
  "vs Mon: 26→28 kg · reps 36→38". No % and no e1RM on the list.
- **Detail (tap):** one chart — per-session best set (kg) as dots with reps labelled, filtered to
  the same `dayKey`; second series toggle "both days" greyed. Title, unit "kg", one-line
  explanation: "Heaviest set each time you did this on this day. Numbers are reps."
- **Baseline copy** — EN: "Baseline: 3 × 12 at 30 kg. Beat it next Chest & Back A." · ES:
  "Marca base: 3 × 12 con 30 kg. Supérala en el próximo Pecho y espalda A."

### 5.4 Best marks — answers Q4
- **Computation:** keep `personalRecords.ts` (needs ≥ PT-RULE-3, default 3, prior sessions;
  typo filter >1.5× kept). Show each record with date, day, set (`35 kg × 12`) and type
  ("heaviest", "most reps at 35 kg").
- **First session = baseline**, listed in a collapsed "Baselines (24)" row, never counted as a record.
- **Empty** — EN: "Records start after a few sessions of each exercise, so a first good day
  doesn't count twice." · ES: "Los récords empiezan tras unas sesiones de cada ejercicio, así un
  primer buen día no cuenta doble."

### 5.5 Volume — answers Q5
- **Visual 1 (the only bar chart):** weekly working sets per muscle group, bar = done, tick =
  planned. Units "sets/week". Explanation line: "Hard sets you logged. Main muscle = 1, helper
  muscle = ½. More is not automatically better — the plan sets the target."
- **Visual 2:** none in week 1. From week 2: small table "sets per week, last 4 weeks" (no line).
- Hide the "common range 10–20" band until the PT approves wording (PT-RULE-4).
- **Empty** — EN: "Log a workout to see sets per muscle." · ES: "Registra un entreno para ver
  series por músculo."
- **Limits note (expandable):** "Doesn't count warm-ups, effort (RIR) or exercise difficulty."

### 5.6 Data hygiene (inline, only when triggered)
- Day mismatch: entries whose `dayKey` differs from the other entries that date →
  EN "2 sets on Fri 9 Oct are saved under Chest & Back A. Fix?" · ES "2 ejercicios del vie 9 oct
  están guardados en Pecho y espalda A. ¿Corregir?" (links to the entry; no auto-change).
- Outliers already flagged by `likelyTypoSetIds`.

## 6. What to remove from the Progress screen
Hero % sentence; streak stat; average % across lifts; e1RM % on lift rows; strength-chart
"+N % this block" takeaway from < PT-RULE-5 points; block tonnage; volume-per-session %;
push:pull and upper:lower bars; range toggle (until 2 blocks); per-exercise VolumeTrend on the
Plan tab (replace with the 5.3 comparison line). e1RM may stay in detail as a secondary,
labelled "estimate" (PT decision).
